**Issue 1 — Parser robustness. CONFIRMED.** An oversized integer literal in a model reply (a 6,000-digit number) makes `json.loads` raise a plain `ValueError` — the interpreter's int-string conversion limit (4,300 digits) — which is not a `JSONDecodeError`. `live.py`'s `_parse_json_object` caught only `JSONDecodeError`/`TypeError`, so the exception escaped `LivePipeline.run()` entirely: no stopped trace, no record. (Also tested: deeply nested replies, which on this interpreter parse or fail closed without escaping; the envelope parse inside `model.py`'s clients is contained by the stage-level guard in `live.py`.) **Fix:** `_parse_json_object` now converts `ValueError`, `TypeError`, and `RecursionError` into `_FormatFailure` — every parse failure fails closed with the documented stopped trace. This was never an unauthorized-release hole (nothing was released); it was a hole in the record.

**Issue 2 — Audit accuracy. CONFIRMED, both parts.** (a) When two different leniency clauses split the cover of one hard clause (L-wrong covers 'wrongdoing', L-dec covers 'deception'), the gate's decision was right but the recorded detail named only the first clause — the audit trail under-reported the leniency granted. **Fix:** when more than one distinct clause covers, the detail names every covering clause and the signal it covers; the single-clause wording is byte-identical to before (the shipped-library goldens pass unchanged). (b) In a three-party conflict (A: priority 10, stop; B: priority 0, proceed; C: priority 0, stop), A governs under R1 — but C was recorded as "prevails" and the (B, C) pair record named C its winner under R1. C decided nothing; it merely agreed with the outcome. **Fix:** "prevails" and pair "winner" now require membership in the decisive set; a non-governing clause whose directive matches the outcome is recorded as "concurs_with_outcome", naming the governing clause(s); a pair of non-decisive clauses records no winner. The R2 trace also now lists each tied clause's own scope when the tied scopes differ as strings, instead of attributing the first clause's scope to all.
